# MIST – Montreal Imaging Stress Task

## Overview

This repository contains a custom implementation of the **Montreal Imaging Stress Task (MIST)** developed in Python using PsychoPy.

The task is designed to investigate responses to cognitive demand and psychosocial stress through timed arithmetic tasks, performance feedback, and social-evaluative cues.

The experimental procedure includes three main phases:

1. **Baseline:** a 5-minute resting period.
2. **Cognitive phase:** a 10-minute arithmetic task without the stress-related time limit.
3. **Stress phase:** a 10-minute arithmetic task with time pressure and social-evaluative feedback.

The task dynamically adjusts arithmetic difficulty according to participants' performance. Behavioral responses and timing information are recorded for subsequent analysis.

This implementation is a customized version of the MIST and should not be assumed to reproduce every feature of the original protocol.

## Repository structure

| File | Description |
|---|---|
| `mainmistv2.py` | Main experimental script. Controls the experimental sequence, instructions, phase timing, feedback, and data logging. |
| `mistskinv2.py` | Generates arithmetic equations at different difficulty levels and implements the adaptive difficulty algorithm. |
| `trialmist.py` | Implements individual trials, stimulus presentation, response collection, time-pressure feedback, and the visual social-evaluation display. |

- Python 3

- Standard Python libraries: `random` and `time`

pip install psychopy

## Installation and execution

1. Clone or download this repository.
2. Ensure that all three Python scripts are located in the same directory.
3. Install PsychoPy in the appropriate Python environment.
4. Create a `data/` directory in the project folder if it does not already exist.
5. Run the main script:

```bash
python mainmistv2.py
```

At startup, a dialog prompts the experimenter to enter the participant identifier and session information.

The experiment runs in full-screen mode. Participants follow the on-screen instructions and use the keyboard to submit their answers.

Pressing `Escape` terminates the PsychoPy application.

## Experimental procedure

### 1. Baseline

Participants are instructed to relax for five minutes before beginning the arithmetic tasks.

The start and end of the baseline period are recorded with Unix timestamps.

### 2. Cognitive phase

Participants solve arithmetic equations without the stress-related response deadline. Every new trial (a new mathematical operation) is marked by a Unix timestamp.

The initial difficulty level is `easy1`. Difficulty is adjusted according to the participant's accumulated correct and incorrect responses.

### 3. Stress phase

Participants perform arithmetic tasks under time pressure and social-evaluative cues. Every new trial (a new mathematical operation) is marked by a Unix timestamp.

The stress phase introduces:

- A maximum response time of 6 seconds per trial.
- A visual bar representing the remaining response time.
- A colored social-evaluation bar.
- Visual indicators representing the participant's performance estimate and a comparison reference.
- Performance feedback following each response.

The phase is designed to introduce time pressure and social-evaluative elements associated with stress induction.

## Adaptive arithmetic difficulty

Arithmetic equations are generated by `mistskinv2.py` at five difficulty levels:

| Level | Difficulty | Arithmetic operations |
|---|---|---|
| 0 | `easy1` | Addition and subtraction |
| 1 | `easy2` | Addition and subtraction with three operands |
| 2 | `med1` | Addition, subtraction, and multiplication |
| 3 | `med2` | Multiplication and subtraction, including larger operands |
| 4 | `hard` | Addition, subtraction, multiplication, and division |

Only equations producing integer results between 0 and 9 are returned, allowing responses to be entered using a single digit.

The difficulty adjustment thresholds differ between phases:

- **Cognitive phase:** difficulty increases after five correct responses and decreases after five errors.
- **Stress phase:** difficulty increases after two correct responses and decreases after four errors.

The difficulty level is bounded between `easy1` and `hard`.

## Data collection

The experiment records trial-level behavioral data and timestamps using PsychoPy's `ExperimentHandler`.

The main variables include:

| Variable | Description |
|---|---|
| `participant` | Participant identifier supplied at startup. |
| `session` | Session identifier. |
| `trial` | Trial index within the current phase. |
| `phase` | Experimental phase: `baseline`, `cognitive`, or `stress`. |
| `event` | Event type, such as trial, phase start, or phase end. |
| `equation` | Arithmetic equation presented. |
| `response` | Participant's numerical response. |
| `correct` | Response accuracy: 1 for correct, 0 otherwise. |
| `rt` | Response time in seconds. |
| `timeout` | Indicates whether a response deadline was exceeded. |
| `difficulty` | Difficulty level associated with the trial. |
| `usrAvg` | Internal performance estimate updated after correct responses. |
| `unix_time` | Unix timestamp in seconds. |
| `exp_time` | Elapsed experiment time in seconds. |

For baseline events, phase boundaries are recorded with their corresponding timestamps.

## Output files

The experiment saves data in the `data/` directory using the participant identifier:

```text
data/
└── <participant_id>_MIST.csv
└── <participant_id>_MIST.psydat
```

- **CSV:** tabular experimental data for inspection and statistical analysis.
- **PSYDAT:** PsychoPy's serialized experiment data.

Output files should be checked after each session to confirm that data have been saved correctly.

## Technical notes

- Phase durations are specified in seconds in `mainmistv2.py`.
- The baseline lasts 300 seconds; both task phases are configured for 600 seconds.
- Response deadlines are defined in `trialmist.py`.
- Equation generation and adaptive difficulty are implemented in `mistskinv2.py`.
- Experimental timestamps are recorded using both Unix time and the experiment's elapsed-time clock.
- The social-evaluation display is generated programmatically and uses an internal performance estimate rather than a measured real-time peer average.
